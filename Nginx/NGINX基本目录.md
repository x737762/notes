# NGINX 基本功能

NGINX 是一个功能强大的 Web 服务器和反向代理服务器，广泛用于处理高并发、负载均衡、缓存等任务。以下是 NGINX 的基本功能：

- **静态文件服务**：高效地处理并传输静态资源，如 HTML、CSS、图片等。

- **反向代理**：将客户端请求转发到后端服务器，支持负载均衡和健康检查。
- **动静分离**：静态内容由 NGINX 处理，动态内容转发给后端处理。
- **负载均衡**：支持多种算法，将流量分配到多个后端服务器上。
- **缓存**：缓存静态资源和代理内容，减少服务器负载，加快响应速度。
- **安全与访问控制**：支持 SSL/TLS 加密，基于 IP 的访问控制和请求限流。
- **日志管理**：记录访问日志和错误日志，便于监控和排查问题。
- **URL 重写与重定向**：灵活处理 URL 重写和重定向，适用于 SEO 优化等场景。
- **WebSocket 代理**：支持 WebSocket 协议，实现双向实时通信。
- **内容压缩**：通过 Gzip 压缩减少传输数据量，加快加载速度。



## 基本目录结构

`NGINX`目录在 `/usr/local/nginx`。（编译安装）

~~~bash
/usr/local/nginx
├── conf             # 配置文件目录
│   └── nginx.conf   # 主配置文件
├── html             # 默认网站资源目录
├── logs             # 默认日志目录
│   └── nginx.pid    # 记录nginx主进程id号
└── sbin 
    └── nginx        # 主进程文件
~~~



## 基本运行原理

### 1. 启动 NGINX：

- 当启动 NGINX 时，首先会创建一个主进程（`master`）。该进程主要负责管理 NGINX 的整体运行，包括读取和解析配置文件，管理子进程等。

### 2. 读取并校验配置文件：

- 主进程启动后，会读取 NGINX 的配置文件（通常是 `nginx.conf`）。在这个过程中，主进程会校验配置文件的正确性。如果配置文件有错误，Nginx 会报错并停止启动过程。

### 3. 启动子进程（`worker`）：

- 如果配置文件校验通过，主进程会根据配置文件的设定启动一个或多个子进程（`worker`）。每个子进程独立处理网络请求，负责具体的请求处理工作。

### 4. 等待并接收用户请求：

- 子进程启动后，进入事件循环，开始等待和接收来自客户端的请求。Nginx 的子进程会基于事件驱动的方式处理这些请求，能够高效地处理大量并发连接。

### 5. 处理用户请求：

- 当有用户请求到达时，子进程会根据配置文件的内容进行处理。这个处理过程可能包括：提供静态资源（如 HTML、CSS、图片等），执行反向代理，将请求转发到后端服务器，或执行负载均衡等。



**注意：**主进程不处理请求，只负责协调子进程。它的主要职责是管理子进程的生命周期，如启动、重启和关闭子进程。当接收到如 `reload` 等信号时，主进程会重新加载配置文件，并根据新的配置文件来管理子进程。



## NGINX 最小配置文件

~~~bash
worker_processes  1;  # 开启的进程数，通常设置为服务器的 CPU 核心数以优化性能或者auto。

events {	# events模块，用于定义网络连接处理的核心参数
    worker_connections  1024; # 每个工作进程的最大连接数，决定了并发处理能力。
}

http { 		# http 模块，定义了 HTTP 服务的全局配置。
    include       mime.types;	# 引入 MIME 类型配置文件，用于识别不同类型的文件。
    default_type  application/octet-stream; # 默认类型，如果在 MIME 配置文件中未找到对应类型，则使用此默认类型。

    sendfile        on;		# 启用 sendfile 优化，直接将文件传输到客户端，而不经过用户空间，这样可以提高传输效率。开启：文件由由网络接口返回；关闭：文件先由NGINX读取，然后再交给网络接口返回。

    keepalive_timeout  65;  # 设置客户端连接保持活动的超时时间，单位为秒。

    server { # server 模块，配置一个虚拟主机（Virtual Host），处理特定的主机名和端口号的请求。
        listen       80; # 监听的端口号，通常是 HTTP 的默认端口 80。
        server_name  localhost; # 该服务器的主机名，可以是域名、IP 地址或主机名。

        location / { # location 块，定义了如何处理以特定 URI 开头的请求。
            root   html; # 设置根目录，该目录下的文件将被映射为 URI 请求的资源。
            index  index.html index.htm; # 配置默认页面，当请求的 URI 是目录时，自动查找这些文件名并返回。
        }
        
        error_page   500 502 503 504  /50x.html;  #  自定义错误页面，处理特定 HTTP 错误码 500、502、503、504。发生服务错误的时候，会跳转到/50.html
        location = /50x.html {  # 精确匹配 URI "/50x.html"，当发生错误时，会显示这个页面。
            root   html; # 错误页面的根目录位置。
        }
    }
}

~~~
